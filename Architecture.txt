Here is the simplified version of that technical document. Think of it as the blueprint for your "No Proxy" attendance app.

1. The Core Concept
You are building a mobile app (that is actually a website wrapped inside an app shell) to automate attendance.

The Goal: Stop students from marking attendance for friends ("proxies").

The Method: The app proves the student is physically in the class by checking which Wi-Fi they are connected to and their Location.

2. How the App Works (Step-by-Step)
Step 1: Login

Everyone uses their college email (@pccoepune.org).

Teachers get a special dashboard.

Students get a simple "Mark Attendance" button.

Step 2: The "Lock" (Anti-Cheating)

When a student logs in, the app records their phone's unique ID.

Rule: You can't log in on two phones at once. This prevents one student from carrying two phones to mark for a friend.

Step 3: Teacher Starts Class

The teacher clicks "Start Attendance" on their phone.

The server tells everyone's app: "Attendance is open for 5 minutes!"

Step 4: Student Marks Attendance

The student connects to the specific Class Wi-Fi (or Hotspot).

They click "Mark Attendance."

The Check: The app secretly checks:

Are you connected to the right Wi-Fi?

Is your GPS location near the class?

Is this your registered phone?

If YES: Attendance marked. ✅

If NO: "Cannot verify location/network." ❌

Step 5: No Internet? No Problem.

If the internet is down but the student is connected to the router, the app saves the attendance on the phone.

It automatically uploads it to the server when the internet comes back (up to 24 hours later).

3. The Tech Stack (The Tools You Use)
Frontend (The App): Built with React (standard web code). It uses a tool called Capacitor to make it run on Android/iOS like a real native app.

Backend ( The Brain): Built with Python (FastAPI). It handles the logic and "talks" to the database.

Database (The Storage): PostgreSQL. A giant spreadsheet that stores users, attendance logs, and device IDs.

Real-time: Uses WebSockets. This is like a direct phone line between the server and the app so notifications (like "Class Started") happen instantly without refreshing.

4. Admin & Security
Admins: Can see who is attending and download Excel sheets of attendance.

Security: Only allows Google logins from your college domain. It blocks "fake" GPS apps and keeps a log of every device used.


Improvements : 

1) Detect "Mock Locations" (Critical for Android):

The Flaw: Android allows developers to "fake" their GPS location for testing. Students will use this to sit in the canteen and appear to be in the classroom.

The Fix: Use a capacitor plugin (like capacitor-detect-mock-location) to check if the location is genuine. If "Mock Location" is detected, block the attendance.

2) The Flaw: On iPhones (iOS), getting the Wi-Fi BSSID (MAC address) is very difficult due to privacy restrictions. A student could just be on the Wi-Fi but outside the door.

The Fix: Display a 3-digit code on the Teacher’s screen that refreshes every 30 seconds. The student must enter this code to mark attendance. This proves they can see the screen (are inside the room).

3) Optional - The "Emergency Reset" for Device Locking:

The Flaw: You have a 12-hour lock. What if a student's phone runs out of battery or breaks right before class?

The Fix: Allow 1 "Emergency Device Switch" per month. If they use it, it flags the record for the admin to check, but lets them mark attendance.
